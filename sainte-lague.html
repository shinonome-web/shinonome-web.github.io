日本の選挙で使われる「ドント方式」と何が違う？割る数を変えるだけで変わる議席配分の仕組みを体験しよう

÷1,2,3

ドント方式（日本など）

得票数を 1, 2, 3, 4... と整数で割る方式。得票が多い大政党にやや有利になり、政権安定に繋がりやすいとされます。

÷1,3,5

サン＝ラグ方式 メイン

得票数を 1, 3, 5, 7... と奇数で割る方式。2議席目以降のハードルが高く、中小政党にも得票率通り公平に配分されます。

÷1.4,3

修正サン＝ラグ方式（北欧など）

最初だけ 1.4 で割り、以降は 3, 5, 7... で割る方式。公平さを保ちつつ、極小政党の乱立を少し抑えます。

割り算の計算表（1議席ずつ決まるプロセス）

割った後の数字（商）が大きい順に 1位、2位、3位... と議席が配分されます。

直感ポイント：なぜサン＝ラグ方式は「1, 3, 5, 7...」と奇数で割るの？

💡 実は「四捨五入」とまったく同じことをしています！

普通の四捨五入では、計算結果が 0.5以上 なら1議席、1.5以上 なら2議席、2.5以上 なら3議席に繰り上がりますよね。

この境界線である「0.5 : 1.5 : 2.5 : 3.5 ...」をすべて2倍して整数にしてみてください。すると…

0.5 : 1.5 : 2.5 : 3.5 ＝ 1 : 3 : 5 : 7

⚖️ ドント方式は「切り捨て」、サン＝ラグ方式は「四捨五入」

  • ドント方式 (1 : 2 : 3 : 4) は、1.0、2.0、3.0に達しないと次の議席がもらえない「端数切り捨て」と同じ性質を持ちます。そのため、端数が切り捨てられやすい小政党が不利になります。
  • サン＝ラグ方式 (1 : 3 : 5 : 7) は、0.5、1.5、2.5を超えた政党から順に議席を与える「四捨五入」と同じ性質を持つため、大政党にも小政党にも偏らないもっとも公平な配分になります。
サン＝ラグ方式 (Sainte-Laguë method / ウェブスター方式) インタラクティブ教材

サン＝ラグ方式とは？（3分でわかる解説）

サン＝ラグ方式（Sainte-Laguë method）は、1910年にフランスの数学者アンドレ・サン＝ラグが考案した比例代表制の議席配分アルゴリズムです（アメリカでは考案者の名からウェブスター方式とも呼ばれます）。

計算の手順

  1. 各政党の得票数を 1, 3, 5, 7, 9...（2n - 1 の奇数） で割ります。
  2. 計算して出た答え（商）を、全政党まとめて大きい順に並べます。
  3. 配分する議席数（定数）に達するまで、上から順番に1議席ずつ割り当てます。

採用している主な国

  • 純粋なサン＝ラグ方式： ドイツ（連邦議会）、ニュージーランド、ラトビアなど
  • 修正サン＝ラグ方式（最初だけ1.4で割る）： スウェーデン、ノルウェー、デンマークなど
  • ドント方式（参考）： 日本（衆議院・参議院の比例代表）、スペイン、ベルギーなど

GitHub Pages (github.io) で公開する手順

このWebアプリは外部のビルドツールを使わず、1つの index.html ファイルのみで完全に動作するように設計されています。以下の3ステップで今すぐ無料公開できます。

ステップ 1: リポジトリの作成

GitHubにログインし、新しいPublicリポジトリ（例: sainte-lague-simulator）を作成します。

ステップ 2: index.html のアップロード

このファイルのコードを index.html という名前で保存し、作成したリポジトリにアップロード（Commit）します。

ステップ 3: GitHub Pages を有効化

リポジトリの Settings → 左メニューの Pages を開き、Branch を main (または master) にして Save を押します。数分後に https://あなたのID.github.io/リポジトリ名/ で公開されます！

既にコミット済みの index.html を編集（更新）する場合
  1. GitHubのリポジトリ画面で index.html をクリックして開きます。
  2. 画面右上の鉛筆アイコン（Edit this file）をクリックするか、キーボードの e キーを押します。
  3. 古いコードをすべて選択して削除し、新しいコードを貼り付けます。
  4. 右上の緑色の Commit changes... ボタンを押し、確認画面でもう一度 Commit changes を押せば更新完了です！（1〜2分でWebサイトにも反映されます）
